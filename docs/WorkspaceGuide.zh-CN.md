# Deskflow 1.29.0 使用说明

本版本面向 Windows 连接实体键鼠、Mac 接收输入的使用方式。显示器、声音、文件和键盘选项均放回原有“服务端配置”或“客户端配置”窗口；显示器画布直接嵌在服务端页面中。

## 安装与首次连接

Windows 安装包适用于 x64；Mac 安装包适用于 Apple Silicon（arm64），最低系统版本为 macOS 15。

1. 从两端菜单栏或托盘的“退出”结束旧程序，再安装更新。若旧 Windows 安装器仍显示服务启动失败，先取消并等待回滚完成，再运行新版安装器。
2. Windows 安装 x64 MSI。Mac 原生键盘输入建议使用完整 PKG 安装包，将 Deskflow 与键盘组件安装到“应用程序”和对应系统位置。两端同时使用本次提供的版本，原有电脑名称、证书信任和设置可以保留。
3. Windows 选择服务端，Mac 选择客户端，输入 Windows 的 IP 或主机名。首次连接时核对并接受对方的证书指纹。
4. macOS 根据系统提示，为实际运行的 Deskflow 应用授予辅助功能和输入监控权限。升级后若授权仍指向旧副本，重新选择“应用程序”里的新副本。
5. 在 Windows 打开原“服务端配置”，设置显示器、游戏保护、声音和文件；在 Mac 打开原“客户端配置”，设置键盘与鼠标、声音、文件与缓存。

Windows MSI 与免安装 ZIP 均携带匹配的 Visual C++ 运行库，无需预先另装运行库。免安装版没有系统服务，不能在 UAC 提示或登录界面接管输入；需要这些能力时使用 MSI。

Mac 完整 PKG 包含虚拟 HID 键盘所需组件。可选 DMG 主要用于普通应用部署和兼容输入，不会通过拖入“应用程序”自动安装系统级键盘组件。虚拟键盘需要完整安装包建立的受保护应用与组件位置。

Deskflow 主程序使用本地签名，主安装包未经过 Apple 公证；系统如阻止首次打开，可在“系统设置 → 隐私与安全性”中打开已确认来源的应用。虚拟 HID 驱动组件采用 Karabiner-DriverKit-VirtualHIDDevice 8.7.0 上游发行版本，保留其代码签名，提供者为 Fumihiko Takayama（G43BCU2T37）。扩展批准按 macOS 正常提示完成。

键鼠默认使用 TCP 24800，声音、文件和显示器信息使用 TCP 24801。自定义键鼠端口时，资源连接使用该端口加一。MSI 为对应程序配置防火墙规则；自定义防火墙需允许两端实际使用的端口。

两端主窗口可以关闭并留在托盘，声音和文件功能继续运行。停止共享或从托盘完全退出程序会结束相应连接；再次打开配置窗口后，仍可以查看和管理已经接收的文件与缓存。

## 配置窗口与保存规则

Windows“服务端配置”包含显示器与电脑、热键、高级、声音、文件与缓存等页面。Mac“客户端配置”包含键盘与鼠标、声音、文件与缓存。

显示器画布、声音选项和文件选项随所在配置窗口一起保存。点击“保存”提交修改，点击“取消”放弃尚未保存的修改；画布内没有第二套保存按钮。仅改变显示器位置、声音或文件选项时，不会为了保存设置而重启键鼠核心。

文件页中的取消传输、打开位置、删除缓存、清理缓存和清除历史是即时管理操作，不随随后取消配置窗口撤销。清除历史与删除文件是两个独立操作。

## Mac 物理按键与虚拟 HID 键盘

原生输入的目标是让 Mac 按自己的键盘布局和输入法解释 Windows 键盘上的物理按键。Windows 本机使用时继续保留原生输入；切到 Mac 时，两端通过 1.10 协议协商物理按键通道，由 Mac 虚拟 HID 键盘重建输入。

1. 使用完整 Mac PKG 安装包安装或升级，并启动“应用程序”中的 Deskflow。
2. 打开 Mac“客户端配置 → 键盘与鼠标”，点击“设置虚拟键盘”。按提示完成组件设置，并在 macOS 系统设置中批准 Karabiner 虚拟 HID 扩展；若系统要求重启，重启后再继续。
3. 开启“使用虚拟 HID 键盘接收物理按键”并保存，重新建立与 Windows 的连接。
4. 查看同一区域的状态文字。组件已安装或已就绪，表示系统组件可用；连接已协商物理输入，表示双方支持该通道；正在通过虚拟 HID 接收物理按键，才表示当前控制确实使用此通道。

输入法和 Caps Lock 按 Mac 本机设置处理。需要 Caps 切换中英文时，在 macOS 的键盘／输入源设置中配置该行为；短按、长按和具体输入法模式以系统及输入法实际行为为准。Deskflow 不把 Windows 的 Caps 锁定状态当作 Mac 必须沿用的状态。

勾选原生输入选项后，原来的 Caps 输入源特判和“跟随服务端输入语言”控件会停用，但原保存值保留；连接实际回退到兼容输入时仍按原有设置处理。Ctrl、Alt、Win 等修饰键的对应关系仍可在原电脑设置中调整。

旧版本服务端、非支持的源端或尚未就绪的键盘组件会让连接使用兼容输入，状态区会明确说明。组件准备好后需要重新连接；不要仅凭复选框已勾选就判断物理通道已经启用。键盘广播使用兼容输入。

普通物理按键交给 Mac 输入法组合中文，与“宏直接生成一段 Unicode 文本”是不同情况。标准 ASCII、常用特殊键和媒体键的生成快捷键可以使用原生通道；任意 Unicode 或厂商专用生成宏可能报告不支持，需要时使用兼容模式。笔记本 Fn 与厂商自定义键还取决于源设备是否向系统上报。

本次设备层原生化针对键盘，鼠标仍采用现有的事件投递和坐标路由。Windows 实体键盘的大小写指示灯仍跟随 Windows 本机状态，Mac 输入源和大小写状态以 Mac 显示为准；本版没有跨电脑同步键盘指示灯。

## 兼容输入与 Caps 切换

未开启原生键盘输入时，Deskflow 使用兼容的按键映射和事件投递。在 Mac“客户端配置 → 键盘与鼠标”中，可开启“使用 Caps Lock 切换此 Mac 的输入法”。

该选项在 Mac 已启用的 ASCII 可用输入源与非 ASCII 输入源之间切换，例如 ABC 与中文拼音，保持 Mac 输入源独立于 Windows。每次按下只切换一次，按键重复不会连续切换。

兼容模式的 Caps 特判不提供“长按 Caps 开启大写锁定”；输入大写可使用 Shift。第三方输入法内部的中英文模式不一定对应两个系统输入源，必要时同时添加系统 ABC 与所用中文输入源。

## Windows 全屏游戏保护

在 Windows“服务端配置 → 高级 → 切换”中开启“全屏游戏时将键盘和鼠标保留在本机”。

自动保护要求前台窗口处于全屏，并且检测到鼠标限制或独占 Direct3D 全屏。仅窗口内限制鼠标、浏览器或视频进入普通全屏，不会单凭这一项触发保护。识别依据是窗口和输入状态，不能视为对所有游戏的准确分类。

若某款游戏未被自动识别，点击同一区域的“添加游戏”，选择实际运行的游戏 EXE 并保存。例如，Windows 只有一块屏幕时，无边框游戏限制到整块屏幕的状态可能无法与未限制状态区分，可以通过指定程序补充。程序列表最多 64 项；指定的游戏仍须处于前台全屏，窗口模式不会因此一直锁住键鼠。

保护只暂停自动跨电脑。声音、文件连接继续工作，按电脑名或方向主动切换的快捷键仍可使用。手动锁定独立生效；默认 Scroll Lock 可切换手动锁定，前提是没有禁用或覆盖该快捷键。

## 每块显示器直接在服务端排列

1. 两端启动并连接后，打开 Windows“服务端配置 → 显示器与电脑”。画布直接位于这个页面。
2. 开启“分别排列和路由每块显示器”。
3. 选择显示器，点击“识别所选显示器”，与实际屏幕对应。
4. 拖动屏幕，让需要连接的边缘贴合。支持上下错位、局部边缘、竖屏，以及把 Mac 屏幕放在两块 Windows 屏幕中间。
5. 点击配置窗口的“保存”统一应用；点击“取消”放弃本次尚未保存的位置和模式修改。

开启独立显示器模式后，整机网格隐藏，电脑列表只管理名称、别名和键盘设置。鼠标边缘和按方向切换快捷键都采用同一张画布。关闭独立模式后，才使用兼容电脑网格；再次开启时保留已保存的显示器摆放。

不同颜色表示所属电脑，灰色表示离线屏幕。显示器热插拔和元数据刷新会更新原生坐标、大小与在线状态，同时尽量保留正在编辑的位置。屏幕内部不能相互重叠，对不相接的边缘保持在有效显示区域内。

系统自己的显示器排列继续决定本机窗口、最大化等行为。Deskflow 画布控制光标跨屏路线，不修改 Windows 或 macOS 显示设置；自定义路线可以接管原本的同机屏幕接缝。

某台电脑断连或没有显示器信息时，会暂停向它自动跨屏，并保留其位置；其他已连接屏幕仍使用同一画布，不悄悄换回另一套方向关系。所有参与自动跨屏的电脑都需支持显示器元数据。

选择外部服务端配置文件时，文件中的电脑链接关系优先，视觉布局编辑停用。关闭外部配置并保存后，可以继续在原页面编辑显示器。

## Windows 系统声音在 Mac 播放

1. 打开 Windows“服务端配置 → 声音”，开启共享本机系统声音，选择接收客户端并保存。
2. 打开 Mac“客户端配置 → 声音”，开启播放服务端声音，选择 Windows 来源和 Mac 本机输出设备并保存。
3. 保持 Windows 原应用正常播放。鼠标切回 Windows 或游戏保护生效时，声音仍按所选固定路线播放。

声音从 Windows 默认播放端点采集，使用独立加密连接发送 48 kHz 双声道 PCM。Windows 切换默认输出设备后会重建采集；Mac 选择系统默认输出时跟随本机设备变化，选择指定设备后按配置保存。

Windows 本机仍保留原声音。本版本不提供虚拟声卡、麦克风反向共享、独占模式或受保护内容采集。发送与接收互斥，避免声音回环。

播放包含采集、网络和输出设备缓冲，不承诺零延迟。有线网络与有线耳机更适合低延迟使用，蓝牙耳机的延迟会叠加到链路中。

## 文件和文件夹复制粘贴

两端原配置窗口中的“文件与缓存”页提供“共享已复制的文件和文件夹”选项。新配置默认开启；升级保留原有的关闭意图。

在 Windows Explorer 或 Mac Finder 复制文件或文件夹，等待传输记录显示完成，再到另一台电脑的目标文件夹粘贴。接收端先收到真实文件，再发布本机文件剪贴板引用，所以 Finder 与 Explorer 可以识别。源文件始终保留，不执行跨电脑剪切或删除。

“自动接收上限”设为“无大小限制”时，已复制文件自动接收到受管理缓存；设定数值后，超过上限的内容显示为待接收的已复制文件，可以选中并接收。网络慢或文件较大时，在记录中查看进度或取消。

接收期间若你又复制了新内容，程序会保留较新的剪贴板。显示“已接收，保留新的剪贴板”的记录仍可通过“打开接收位置”取用文件。

文件页以原有复制粘贴操作为入口，不再提供拖入文件、选择文件或手动发送区。跨越两台电脑的任意应用之间原生拖放尚不支持。

文件按块传输并校验 SHA256，完成前存放于临时目录，完成后才发布；同名目标采用新名称，不覆盖已有文件。连接中断或取消时，未完成内容不会以最终文件名发布。重连后可重新复制文件发起传输。

支持普通文件与文件夹，每次最多 4096 个目录项。不跟随符号链接、设备文件或 Windows 目录联接，也不提供 macOS 扩展属性、资源叉、ACL 的跨系统保真复制。跨系统文件名需符合 Windows 与 macOS 的共同约束。

## 传输记录与缓存管理

在任一端原配置窗口的“文件与缓存”页，可以查看当前任务和最近的持久传输记录，包括文件、对端电脑、方向、进度、状态和更新时间。退出重开后仍保留历史，最多保存最近 200 条；意外中断的旧任务会标记为已中断。

“接收文件缓存”区域显示缓存目录、实际占用、文件数量和每项使用状态。统计在后台进行；显示正在计算时，可稍后刷新查看完整结果。

- 选中传输记录后，可以取消活动传输或打开已接收文件的位置。
- 选中缓存项目后，可以打开它的位置，或删除未使用的接收副本。
- “清理未使用缓存”批量清理符合管理条件的旧接收副本。
- “清除已完成历史”只清理记录，不删除文件；删除缓存后，对应历史仍可显示缓存已清除。
- 活动传输、当前文件剪贴板引用，以及人工保存的目标受到保护。使用中的缓存会显示对应状态，不能删除。

停止共享后仍可打开配置窗口查看历史和缓存。缓存清理仅管理接收副本，不影响源文件，也不会按历史里的任意路径删除文件。需要保留接收文件时，先通过正常粘贴保存到自己的目标目录。

## 连接状态与排查

左下角状态表示实际键鼠连接，不以后台服务或资源连接已启动代替“已连接”。本版修正了后台连接先接入时消耗状态通知，以及旧重试计时器覆盖新状态的问题。

- 键鼠可用但状态仍异常：检查两端是否均已更新，并完全退出旧副本后重启。仍有异常时保留日志中的当前版本、连接和重连信息。
- 键鼠已连接但没有声音或文件信息：检查两端版本、证书信任和键鼠端口加一的资源端口。
- Mac 显示兼容输入：查看虚拟键盘状态提示，确认使用完整 PKG、组件已启用、扩展已批准，再重新连接两端。组件就绪和当前物理输入启用是两个不同状态。
- 文件不能粘贴：查看是否完成接收、超过自动接收上限、包含特殊文件或不兼容文件名。
- 无法删除缓存：检查是否仍被活动传输或文件剪贴板使用；复制其他内容或等待任务结束后刷新。
- 没有声音：检查 Windows 发送、Mac 接收选项都已保存，且来源、输出设备和 Windows 默认播放端点正确。
- 全屏游戏仍误切：确认保护已开启，并将实际游戏 EXE 加入程序列表。手动锁定快捷键仍可独立使用。

## 验证范围

安装包随附源码版本、构建验证记录与 SHA256。协议、真实 TLS 回环、输入状态、布局路由、文件传输与校验、历史和缓存保护、界面保存／取消、连接状态观察者等自动检查，以随包记录为准。

虚拟 HID 系统扩展需要安装后由用户按 macOS 提示批准。构建和 CI 不会代替用户激活扩展；自动检查不能证明特定实体键盘、第三方输入法、游戏或声音设备已完成联机验收。实际双机手感、游戏捕获、Caps 与输入法细节、声卡和蓝牙时延仍需对应设备确认。
