# Deskflow 共享工作台使用说明

本版本面向 Windows 提供键鼠、Mac 接收输入的使用方式，增加 Mac Caps 输入源切换、Windows 全屏防误切、Windows 系统声音共享、双向文件复制和独立显示器布局。

## 安装与首次连接

1. Windows 安装对应的 x64 MSI；Mac 打开 arm64 DMG，将 Deskflow 拖到“应用程序”。两台电脑都使用本次提供的版本。
2. Windows 选择服务端，Mac 选择客户端，输入 Windows 的 IP 或主机名。原有的电脑名称、位置和 TLS 信任配置继续沿用。
3. 首次连接时核对并接受双方证书指纹。共享工作台复用已信任的证书；只接受已经信任的设备。
4. macOS 根据系统提示，为实际运行的 Deskflow 应用授予辅助功能和输入监控权限。升级后若权限指向旧副本，重新选择“应用程序”里的新副本。
5. 打开“编辑 → 共享工作台”（英文界面为 Edit → Shared workspace）。顶部显示工作台端口和已连接的电脑数量。

键鼠默认使用 TCP 24800，共享工作台使用 TCP 24801。自定义键鼠端口时，工作台使用该端口加一。Windows MSI 为 core 程序添加防火墙规则；自定义防火墙或路由规则需要允许两端使用的工作台端口。

安装包未使用商业开发者证书签名或 Apple 公证。Mac 如阻止首次打开，可通过“系统设置 → 隐私与安全性”打开已确认来源的应用。Windows 如果提示缺少 Microsoft Visual C++ 运行库，安装微软官方的 Visual C++ 2015–2022 x64 Redistributable 后再运行 MSI。

## Mac 键盘与中英文切换

在 Mac 的“客户端配置”里开启“使用 Caps Lock 切换此 Mac 的输入法”。保存会重启共享进程。

启用后，Caps 在 Mac 已启用的 ASCII 可用输入源与非 ASCII 输入源之间切换，例如 ABC 与中文拼音。切换直接使用 macOS 输入源接口，不依赖固定的 Command/Control/Win 加空格。此模式保持 Mac 的输入语言独立于 Windows。

每次按下只切换一次，按键重复不会连续切换；普通 ASCII 字母同时处理 Windows Caps 状态与 Shift。此版本不提供“长按 Caps 开启大写锁定”；输入大写可以使用 Shift。

第三方输入法内部的中英文模式不一定是两个系统输入源；如果它没有单独暴露输入源，请同时添加系统 ABC 与所用中文输入源。Windows 键盘上的 Ctrl、Alt、Win 修饰键映射仍可在原有电脑配置中调整。

## Windows 全屏与游戏防误切

在 Windows 的“服务端配置”中开启“全屏或应用限制鼠标时，禁止鼠标自动跨电脑”。

当前台无标题栏窗口占满显示器，或应用把鼠标限制在局部范围时，鼠标触碰跨电脑边缘不会自动切到 Mac。全屏视频同样会触发保护。普通最大化窗口不会仅因最大化而触发全屏判定。

自定义的“切换到电脑”或“按方向切换”快捷键仍可主动跳转。手动鼠标锁定独立生效；默认 Scroll Lock 可切换手动锁定，前提是没有关闭或覆盖此功能。开启保护不需要断开键鼠、声音或文件连接。

## Windows 系统声音在 Mac 播放

1. 两端打开“共享工作台 → 声音”。
2. Windows 开启“共享此 Windows 电脑的系统声音”，选择发送目标，点击“应用”。
3. Mac 开启“播放另一台电脑的声音”，选择 Windows 来源和本机输出设备，点击“应用”。
4. 保持 Windows 原应用正常播放。鼠标切回 Windows 或开启全屏保护，不会改变声音去向。

音频从 Windows 默认播放端点采集，使用独立加密连接发送 48 kHz 双声道 PCM。Windows 切换默认输出设备后会重建采集；Mac 使用系统默认输出时跟随默认设备变化。切换指定输出后点击“应用”。

Windows 本机仍会播放原声音。此版本不提供虚拟声卡、麦克风反向共享、独占模式采集或受保护内容采集。发送与接收互斥，避免把远端声音再次采回形成回环。

有线网络和有线耳机更适合低延迟使用。蓝牙耳机本身的延迟会叠加到播放链路。没有设置“声音跟随鼠标”，音频始终使用所选固定路由。

## 文件与文件夹复制

两端“共享工作台 → 文件”默认开启文件剪贴板共享。

在 Windows Explorer 或 Mac Finder 复制文件或文件夹，等待传输栏显示完成，再切到另一台电脑粘贴。接收端发布实际存在的本地文件，所以 Finder 与 Explorer 可以正常识别。复制多份文件时源文件保留，不会执行跨电脑删除或移动。

“自动接收上限”设为“无大小限制”时，复制的文件会自动传到受管理缓存；设置数值后，超过上限的文件只显示为可接收内容。网络慢或文件大时，可以在传输栏观察进度和取消。

也可以选择目标电脑，点击“选择文件”或“选择文件夹”，或把文件拖到窗口内的投放区域。对端选择“保存所选文件到”并指定目录。点击“打开接收位置”查看已完成文件。

文件按块读写并校验 SHA256，完成前保留在临时目录，完成后提交；同名目标采用新名称，不覆盖已有文件。连接中断或取消时保留源文件，未完成内容不会以最终文件名发布。重连后可以重新复制或重新发送。

当前支持普通文件与文件夹，每次最多 4096 个目录项；不跟随符号链接、设备文件或 Windows 目录联接，也不提供 macOS 扩展属性、资源叉、ACL 的跨系统保真复制。存在这些特殊对象时会明确报错。跨系统文件名须符合 Windows 与 macOS 的共同约束，不能用大小写或 Unicode 规范化差异制造同名对象。

窗口内投放区支持拖入文件；直接从任意源应用跨到另一台电脑的任意目标应用进行原生拖放不在本版本支持范围内。日常文件跨电脑操作使用复制粘贴或传输栏。

## 每块显示器独立摆放

1. 两端启动并连接后，打开“共享工作台 → 显示器 → 单独排列显示器”。
2. 开启“分别排列和路由每块显示器”。
3. 点击一块显示器，再点“识别所选显示器”，对照真实屏幕编号。
4. 拖动每块显示器，使相互连接的边缘贴合。支持上下错位、局部边缘、竖屏，以及把 Mac 屏幕放在 Windows 两块屏幕中间。
5. 保存后立即应用。布局只改变 Deskflow 的鼠标路由，不改变系统显示设置。

不同颜色表示所属电脑，灰色表示已断开显示器。显示器重新接入时尽量恢复原位置。缩放与原生坐标分开处理；可以编辑画布中的宽高，调整不同物理尺寸屏幕之间的穿越比例。

所有参与路由的电脑都需支持本版本显示器元数据；连接旧客户端时自动回退到原有整机布局。对不相接的边缘，鼠标保持在有效显示区域内，不会掉到显示器之间的空洞。

## 连接与排查

- 键鼠已连接但工作台显示零设备：检查双方版本、已信任指纹和工作台端口；等待约数秒自动重连。
- 文件尚不能粘贴：查看传输栏是否完成、是否超过自动接收上限、是否包含不支持的特殊文件或不兼容文件名。
- 没有声音：确认 Windows 发送、Mac 接收均已应用，路由来源与输出设备正确，且原应用正常输出到默认播放端点。
- 全屏仍意外切换：确认 Windows 端保护已开启。特定窗口类型可能不被全屏几何规则识别，可使用 Scroll Lock 或配置手动锁定快捷键。
- 显示器位置不对应：使用识别功能重新核对；仅完整接触的画布边缘建立连接，屏幕内部不能相互重叠。

## 验证边界

安装包附带构建版本和 SHA256。自动测试覆盖协议分帧与鉴权、真实 TLS 回环、音频格式转换及有界缓冲、文件传输与校验、显示器路由和输入策略。Windows 与 Mac 各自的构建结果以随包验证记录为准。

真实游戏的鼠标捕获、不同第三方输入法、实体声卡与蓝牙设备的音频时延、两台实体电脑间的使用手感，需要对应硬件联机确认。未实测的项目不表示已经通过实机验收。
